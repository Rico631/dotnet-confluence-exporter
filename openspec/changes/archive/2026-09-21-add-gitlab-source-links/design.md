# Design

## Context

Текущий анализатор получает исходные файлы через Roslyn symbols, но при преобразовании в `HandlerDocumentation` и `MethodDocumentation` сохраняются только имена и сигнатуры. `HandlerDocumentationRenderer` уже принимает `HandlerDocumentationRenderOptions` и умеет строить GitLab commit URL, поэтому новые ссылки должны использовать тот же публичный параметр repository URL и не добавлять внешние зависимости.

## Goals / Non-Goals

**Goals:**

- Сохранить относительный путь каждого handler и метода call tree относительно корня Git-репозитория.
- Добавить в options GitLab reference с default value `main`.
- Генерировать ссылки на файлы GitLab через `/-/blob/{reference}/{relative-path}`.
- Сохранять текущий вывод без ссылок при неполной конфигурации.
- Покрыть URL-построение, fallback и передачу путей тестами.

**Non-Goals:**

- Ссылки на конкретные строки методов.
- Изменение формата существующих commit-ссылок.
- Автоматическое определение default branch через GitLab API.
- Поддержка других систем контроля версий.

## Decisions

1. **Путь хранится в моделях документации.**
   `HandlerDocumentation` получает относительный путь handler-файла, а `MethodDocumentation` получает относительный путь файла метода. Это отделяет анализ исходников от renderer и позволяет рендерить уже подготовленную документацию.

2. **Reference задаётся параметром рендера.**
   В `HandlerDocumentationRenderOptions` добавляется GitLab reference с default value `main`. Выбранная альтернатива, а не извлечение ветки из локального репозитория, делает ссылку явной и предсказуемой для экспортируемой документации.

3. **Относительный путь вычисляется от корня Git-репозитория.**
   Для handler и методов используется путь исходного `SyntaxTree`, нормализованный к `/`. Если корень репозитория или путь определить нельзя, ссылка не создаётся.

4. **URL-кодирование выполняется по сегментам пути.**
   Разделители каталогов сохраняются, а каждый сегмент, reference и repository URL безопасно экранируются перед вставкой в XHTML. Значение href дополнительно HTML-кодируется.

5. **Ссылка оборачивает существующее отображаемое имя.**
   Для handler ссылкой становится его отображаемое имя, для call tree — имя метода. Сигнатура и описание остаются рядом с ссылкой в текущем формате.

## Risks / Trade-offs

- [Risk] Локальный путь проекта может находиться вне Git-репозитория → путь не сохраняется, а renderer использует текстовый fallback.
- [Risk] Локальная ветка и GitLab reference могут не совпадать → reference задаётся явно в options, поэтому вызывающая сторона отвечает за корректную конфигурацию.
- [Risk] Методы внешних библиотек не имеют исходников в текущем репозитории → для них не создаётся ссылка, но call tree продолжает отображаться.
- [Trade-off] Ссылки ведут на файл, а не на строку → URL устойчивее к изменению сигнатур и не требует хранения line span.

## Migration Plan

Изменение обратно совместимо: существующие вызовы `Render` продолжают работать с default reference, а при отсутствии GitLab repository URL HTML остаётся текстовым. После реализации нужно обновить пример конфигурации вызова и выполнить тесты и сборку.
